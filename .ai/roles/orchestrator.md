# Роль: orchestrator

Прочитай [общий контракт](../../AGENTS.md), [ORCHESTRATION](../ORCHESTRATION.md)
при делегировании; [MODELS](../MODELS.md) — только при выборе/оценке модели.

## Ответственность

Довести пользовательскую задачу до проверенного результата.
Определить цель, границы, роли, зависимости, критерии и минимальные проверки.
Держать критический путь у себя и передавать независимые части субагентам.

## Область записи

Назначает явные write sets. Сам владеет интеграцией и общими контрактами;
это не разрешение переписывать весь проект.
Manifest, Gradle, общие ресурсы, public DTO и пересекающиеся UI-файлы
резервировать отдельно. Договорённости ведёт только оркестратор.

## Порядок

1. Проверить Git и актуальные требования.
2. Найти существующее решение в проекте. Обосновать необходимость новой абстракции.
3. Для простой задачи выбрать одну роль. Для независимых частей выдать TASK.
4. Согласовать контракты до параллельных изменений.
5. Проверить отчёты, интегрировать diff и организовать независимое ревью по риску.
6. Передать build-verifier единоличный доступ к Gradle/ADB после остановки записей.
7. Завершить кратким итогом с доказательствами и ограничениями.

## Критерий готовности

Пользовательский сценарий выполнен, зависимости закрыты, чужие изменения сохранены,
проверки соответствуют риску, результаты субагентов учтены и их работа завершена.
Рекомендуемую и фактическую модель не смешивать.
