# Production-релизы и обновление через GitHub

Актуальный репозиторий: [krislechy/Bobyl-TV](https://github.com/krislechy/Bobyl-TV).
Для приложения используются только Releases этого репозитория.

## Подпись и совместимость

Production — вариант `tvRelease`, пакет `com.bobyl.tv`, название «Бобыль».
Он использует минимизацию и сокращение ресурсов и не является отладочным.

Существующий локальный ключ подписи нельзя удалять, менять или генерировать
заново: обновление поверх установленного приложения требует того же сертификата.
Dev (`com.bobyl.tv.dev`) — отдельный пакет, его данные не заменяют production.

Ключи подписи, их пароли, локальные настройки SDK и данные устройств в Git не входят.
Текущая настройка `tvRelease` использует существующий локальный Android-сертификат,
указанный в конфигурации сборки. Это установка APK напрямую, а не публикация в Google Play.

## Подготовка версии

1. Увеличьте `versionCode` и задайте `versionName` в `app/build.gradle.kts`.
2. Подготовьте описание изменений на русском в `docs/releases/`.
3. Соберите и установите Dev в эмулятор разрешённой командой.
4. Сохраните изменения коммитом без личного email и отправьте ветку `main`.
5. Не публикуйте тестовые, отладочные и неподписанные APK как production.

## Сборка без установки на устройство

Из корня репозитория:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\PublishProdGitHub.ps1
```

Скрипт удерживает общую блокировку, выполняет только `assembleTvRelease` и
готовит файлы в `captures/github-production/`. Он не вызывает ADB и не устанавливает
production на телевизор или в эмулятор.

Лог: `captures/publish-prod-github.log`. При ошибке процесс останавливается,
автоматический повтор не выполняется.

## Публикация

Публиковать исходники и выпуск только по явной команде. Установка на устройство
не запускает публикацию в GitHub.

Единая команда создаёт коммит с GitHub noreply, проверяет историю на секреты и
личные данные, отправляет `main`, затем собирает и публикует APK с метаданными:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\PublishGitHub.ps1 -NotesPath .\docs\releases\2.3.10.md -CommitMessage "Обновление интерфейса"
```

Для проверки секретов требуется Gitleaks в PATH или `privacy/gitleaks.exe`
в локальном каталоге инструментов. Лог проверки: `captures/publish-privacy.log`.
Ошибки проверки, отправки и сборки останавливают процесс без автоматических повторов.
Коммит, созданный перед неудачной проверкой, остаётся локальным и не отправляется.

Для отдельно подготовленного и уже отправленного коммита можно использовать
прежнюю команду выпуска ниже.

Нужен авторизованный GitHub CLI с правом записи в репозиторий.
Рабочее дерево должно быть чистым, локальный HEAD — совпадать с отправленной `main`.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\PublishProdGitHub.ps1 -Publish -NotesPath .\docs\releases\2.3.8.md
```

Скрипт загружает APK и метаданные в черновик, затем публикует релиз и делает его
последним. Ключ подписи остаётся на машине сборки.
Один и тот же тег не следует перезаписывать: для следующего выпуска увеличьте версию.

## Файлы релиза

- `bobyl-tv-production-v<версия>.apk` — production-приложение.
- `bobyl-tv-update.json` — имя пакета, номер и название версии,
  имя APK и его SHA-256.

Пример структуры метаданных (значения формирует скрипт, не заполняйте хеш вручную):

```json
{
  "packageName": "com.bobyl.tv",
  "versionCode": 56,
  "versionName": "2.3.8",
  "apk": "bobyl-tv-production-v2.3.8.apk",
  "sha256": "<SHA-256 подготовленного APK>"
}
```

## Поведение приложения

Начиная с 2.3.8, в production есть раздел
**Настройки → Обновление приложения**: проверка, скачивание и установка.
Используется только последний опубликованный обычный релиз; черновики и
предварительные релизы исключены. GitHub-токены и cookies каталога не передаются.

Перед открытием установщика приложение проверяет контрольную сумму,
пакет `com.bobyl.tv`, более высокий номер версии, отсутствие режима отладки
и совпадение подписи с установленным приложением.
На Android может потребоваться разрешить установку из этого источника,
затем повторно нажать «Установить». Окончательное согласие запрашивает Android.

В Dev, benchmark и profile обновления отключены. Приложение не заменяется
скрытно, данные не очищаются. Старые production-версии без этого раздела
нужно один раз обновить вручную APK из нового репозитория.

## Архивный выпуск

Релиз 2.3.7 перенесён как архивная production-сборка. В нём ещё нет механизма
обновления через новый репозиторий. Его исходная закрытая Git-история не публикуется.
