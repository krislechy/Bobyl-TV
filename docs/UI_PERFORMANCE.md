## Что измеряется

Baseline фиксирует текущее рабочее дерево после первого этапа изменений списков.
Измерений до этих изменений нет; считать разницу с HEAD доказанным ускорением нельзя.

Отдельный пакет `com.bobyl.tv.benchmark`: R8, resource shrinking, non-debuggable,
profileable, debug signing. Данные `com.bobyl.tv` и `com.bobyl.tv.dev` не копируются
и не очищаются. Каталог публичный, сеть и картинки живые; сравнивать прогоны нужно
при одинаковом зеркале, числе колонок, режиме экрана и состоянии кэшей.

## Запуск

Из Git-корня: `powershell -NoProfile -File tools/MeasureUiBaseline.ps1`.
Скрипт удерживает общий OS lock на сборку, установку и измерения.
Запуск занимает экран приставки; выполнять в выделенное время тестирования.
Результаты находятся в `captures/ui-baseline-<timestamp>/` (локально, вне Git).

- `instrumentation.txt`: результат тестов, ошибки, показатели.
- `baseline/*.json`: исходные метрики Macrobenchmark.
- `baseline/*.perfetto-trace`: трассы каждого повтора для Perfetto.
- `apk-sha256.txt`, `commit.txt`, `working-tree.patch`: идентификация сборки.
- `display.txt`, `thermal-*.txt`, `memory-after.txt`: условия устройства и PSS.

`StartupBenchmark.coldStartup`: пять запусков нового процесса, `CompilationMode.None`.
Это cold process startup, не обязательный cold disk/image cache. TTID означает
первый кадр Activity, не готовый после сети каталог. TTFD не выдаётся за измеренный
без сигнала готовности экрана.

## Порядок дальнейших работ

1. Получить baseline startup, D-pad scroll Home/Search, Details open/scroll/Back.
2. Зафиксировать P50/P95/P99 CPU frame duration и frame overrun, число кадров,
   jank, PSS и корректность focus. Пропуски данных обозначать как непроверенное.
3. Выбрать изменения по трассам; каждое сравнивать с тем же сценарием и условиями.
4. После стабилизации добавить Baseline Profiles и отдельно измерить их эффект.

Частоту HDMI читать перед каждым прогоном: на 50 Гц период кадра 20 мс,
на 60 Гц — около 16,67 мс. CPU frame duration сама по себе не доказывает отсутствие
jank; учитывать frame overrun и FrameTimeline. PSS после одного запуска не доказывает
отсутствие утечек; для памяти необходим длительный повторяемый прогон.

### Уточнение пункта 3 исходного плана

По текущему коду `SearchInput` уже откладывает запрос подсказок на 400 мс и
отменяет предыдущий LaunchedEffect при смене provider/value. Основной поиск
отправляется явным действием «Найти»; debounce подсказок не означает автопоиск.
`CatalogViewModel.load` уже отменяет прежний job, блокирует дубли одинаковой
первой страницы и параллельную пагинацию. Изменение focus не входит в ключ загрузки.
Первоначально это было установлено чтением кода; следующая итерация добавила
управляемые проверки основного каталога, описанные ниже.

### CatalogRequest и управление пагинацией

Активные provider/section/query/kind теперь представлены immutable CatalogRequest
в CatalogState. UI передаёт выбранные параметры при выборе каталога, а loadMore
и retry берут параметры из ViewModel. Повтор той же выборки не запускает запрос,
включая состояние ошибки; для ошибки требуется явный retry. Автопагинация больше
не повторяет упавшую страницу при изменениях layout. Номер поколения запроса
дополнительно запрещает запоздалой ошибке отменённой операции менять новый экран.
При смене фильтра UI не инициирует пагинацию предыдущей выборки.

Добавлены пять CatalogViewModelTest с управляемым loader и coroutines-test:
дедупликация выбора/пагинации, ошибка второй страницы и повтор именно страницы 2,
поздняя ошибка отменённого запроса, clear во время ответа и остановка на странице
с одними дубликатами. `:app:testDebugUnitTest :app:assembleDebug` — успешно,

## Восстановление страниц после завершения процесса — 2026-09-20

CatalogViewModel сохраняет идентификатор выборки (provider/section/query/kind)
и номер последней успешно загруженной страницы в SavedStateHandle. При создании
новой модели и совпадении выборки страницы загружаются последовательно до
сохранённого номера; при смене фильтра загрузка начинается с первой страницы.
До окончания восстановления основной LazyColumn не измеряется, чтобы короткий
промежуточный список не сбросил сохранённый scroll index. Вместо него показано
«Восстанавливаем каталог…». Пустая/дублирующаяся выдача останавливает загрузку.

Если промежуточная страница падает, уже загруженные данные доступны вместе с
ошибкой; Retry начинает с неудавшейся страницы и продолжает до сохранённой.
Восстановление позиции после такого частичного сбоя отдельно на UI не проверено.
Данные фильмов и bitmap не сохраняются в Bundle; восстановление требует доступа
к provider либо его существующему кэшу и может занять время при большом числе страниц.

Добавлены три теста: последовательное восстановление 1–3 с публикацией готового
списка; несовпадающий фильтр; ошибка страницы 2 и Retry с порядком 1,2,2,3.

полные build/instrumentation-логи локально и выводит только статус, метрики и
короткий хвост ошибки при сбое. Каждый блок получает отдельный каталог, JSON и
Perfetto-трассы. `-CompilationMode None|Partial` выбирает режим; `-CompareProfiles`
запускает четыре блока в порядке None/Partial/Partial/None (ABBA).
Partial требует Baseline Profile (`BaselineProfileMode.Require`), без JIT warmup.
Эти режимы поддерживают StartupBenchmark и CatalogBenchmark. Проверка всех
четырёх блоков обязательна; неуспешный блок останавливает сравнение.

Команда запуска: `./tools/MeasureUiBaseline.ps1 -Serial emulator-5556 -CompareProfiles`.
Холодный запуск проверен на API 34, одинаковом benchmark APK с R8, по пять запусков
в каждом блоке. Артефакты: `captures/ui-baseline-20260926-215457`.
Все четыре блока завершились PASS; установка выполнена через `install -r`.

| Блок | Режим | Медиана TTID, мс |
|---|---|---:|
| 00 | None | 1284,9 |
| 01 | Partial | 1065,0 |
| 02 | Partial | 1031,5 |
| 03 | None | 1122,2 |

Объединённые исходные runs из JSON, по 10 значений на режим:
None — медиана 1135,0 мс (диапазон 1064,0–1593,2), Partial — 1051,8 мс
(960,2–1290,8). Снижение медианы 7,3% — описательный результат этого прогона,
не статистическое доказательство устойчивого ускорения. Заметен разброс и
изменение None между первым и последним блоками. Сравнивается применение всего
упакованного профиля, включая правила библиотек, с отсутствием предварительной
компиляции, а не изолированный вклад только новых правил приложения.
TTID обозначает первый кадр, не полную загрузку каталога. EON не использовался.

Сравнение Home запущено командой с дополнительным параметром

## Поиск после отправки запроса — 2026-09-26

Исправлено сохранение списка подсказок над уже загруженными результатами:
когда searchDraft совпадает с отправленным query (с учётом trim), подсказки
сразу скрываются, а их незавершённый запрос отменяется существующим механизмом
SearchSuggestionsViewModel. Новый текст снова включает подсказки. Результаты
предыдущего поиска сохраняются до отправки нового запроса.

Одна debug-сборка и установка Dev через install -r на emulator-5556 прошли.
Четыре существующие проверки SearchSuggestionsViewModel прошли без ошибок.
Короткий UI-сценарий: matrix → Найти — подсказки исчезли, постеры поднялись
к верхней части списка; D-pad перешёл на карточку «Сбой в матрице».
После изменения текста на friends появились пять LEGO Friends-подсказок,
прежние результаты Matrix остались до нового submit. Локальные снимки состояния:
captures/search-submitted.xml и captures/search-edited.xml.
Бенчмарки и Perfetto не запускались; на EON изменений не делалось.

## Увеличенный шрифт — 2026-09-27

обрезание текста. CinematicButton и RailItem теперь используют минимальную
высоту вместо фиксированной (48 и 54 dp), вертикальные отступы и максимум
две строки с многоточием. Кнопка растёт вместе с текстом; полная подпись

Одна assembleDebug и install -r на emulator-5556 прошли. Снимки

обрезания. Размер шрифта возвращён к 1.0; переход D-pad между рядами Home проверен.
До изменения Back вернул фокус на выбранную третью подсказку, однако успешная
загрузка её Details в короткой проверке не подтверждена. Полный маршрут
поля ввода/подсказок после изменения конфигурации отдельно не закрыт.
Бенчмарки не запускались, EON не использовался.

## Вертикальная навигация поля поиска — 2026-09-27

В Input для searchField добавлена явная обработка D-pad Up/Down через
FocusManager. Left/Right сохраняют прежнее перемещение курсора и выход
на границе текста; при выделенном тексте обработка не перехватывается.
Другие поля ввода не изменены.

assembleDebug и установка Dev через install -r на emulator-5556 прошли.
Проверено на friends: после закрытия экранной клавиатуры Down переводит
фокус на первую LEGO Friends-подсказку, Up возвращает в редактор, Left
оставляет фокус в редакторе, Down из середины текста снова ведёт к подсказке.
Первые попытки с открытой IME оставляли фокус в поле: dumpsys подтвердил
mInputShown=true / mIsInputViewShown=true. Их нельзя считать доказательством
ошибки навигации самого приложения. Бенчмарки не запускались.

## Семантика навигации — 2026-09-27

Отменено 2026-09-28 по указанию пользователя: добавленные semantics у RailItem
и CinematicButton удалены. Дальнейшие accessibility/TalkBack работы исключены.
Ниже сохранена история проверки до отмены.

FieldAction уже передавал подпись, роль Button и состояние enabled. У RailItem
выбранный раздел раньше выделялся только визуально: XML для активного «Поиска»
показывал selected=false. Добавлены selected, Role.Tab и mergeDescendants;
