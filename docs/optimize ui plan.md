По текущему коду оптимизацию UI следует вести от измерений к точечным изменениям. Исследование files/uxui.md использую как набор рекомендаций, а порядок ниже основан на найденной реализации.

Уточнение области работ на 2026-09-28: по указанию пользователя дальнейшие
бенчмарки и accessibility/TalkBack исключены. Практические изменения и целевые
UI-проверки завершены, короткий маршрут проверен на EON. Исходные пункты ниже
сохранены; фактическое выполнение и непроверенные условия отражены в
[отчёте](UI_PERFORMANCE.md). Полное выполнение исходных критериев производительности
не заявляется.

1. Сначала зафиксировать baseline
   - Собрать tvRelease или другой недебажный вариант.
   - Измерить холодный запуск, первый кадр Home, прокрутку каталога, открытие Details, поиск и возврат назад.
   - Использовать Macrobenchmark и Perfetto.
   - Проверить D-pad-сценарии на EON Smart Box: начальный focus, переход между карточками, Back и восстановление выбранной карточки.
   - Зафиксировать метрики: startup time, frame time, jank percentage, количество recomposition и потребление памяти.
Критерии: scrolling без систематических пропусков кадров; для 60 Hz основная работа кадра около 16 мс или меньше.
2. Устранить наиболее вероятное узкое место в списках
В ConnectedCatalog уже используется один LazyColumn и обычный Row карточек с ключом строки (ConnectedCatalog.kt:121-183). Это решение стоит сохранить.
В PagedFilms остаётся вложенная структура LazyColumn → LazyRow (BrowseScreens.kt:63-68). План:
- заменить вложенный LazyRow на обычный Row, если число карточек ограничено columns;
- сохранить стабильные ключи фильмов;
- не пересоздавать films.chunked(columns) при каждом не связанном с каталогом изменении;
- добавить автоматическую подгрузку по видимому индексу, как в основном каталоге;
- оставить кнопку «Загрузить ещё» резервным вариантом.
3. Стабилизировать модель состояния
ConnectedCatalog хранит много состояния непосредственно в одном composable (ConnectedCatalog.kt:51-109), а CatalogViewModel уже выполняет дедупликацию на Dispatchers.Default (CatalogViewModel.kt:25-50).
Следующий этап:
- выделить неизменяемый CatalogUiState;
- перенести выбор раздела, тип контента, поисковый запрос и состояние загрузки в ViewModel там, где они влияют на загрузку данных;
- оставить в composable только визуальное состояние: focus, открытый диалог и локальную прокрутку;
- добавить debounce для поиска;
- не запускать повторную загрузку при изменении только focus или выбранной карточки;
- проверить отмену устаревших запросов при быстром переключении разделов.
4. Оптимизировать изображения
Coil уже подключён (app/build.gradle.kts:68-69) и используется через AsyncImage. Нужно проверить конфигурацию:
- создать один application-level ImageLoader;
- задавать размер загрузки под фактический размер постера;
- не декодировать оригинальные изображения для карточек;
- использовать одинаковый aspect ratio и placeholder до загрузки;
- ограничить backdrop Details реальным размером окна;
- проверить memory cache после длительной прокрутки Home и Search;
- не хранить Bitmap в UI state.
Особое внимание — Details: сейчас изображение может занимать почти весь экран (ConnectedCatalog.kt:280-285), а poster загружается повторно в блоке метаданных (ConnectedCatalog.kt:316-320). Следует проверить, можно ли переиспользовать результат загрузки без ухудшения качества.
5. Снизить стоимость focus-анимаций
PosterCard, RailItem и CinematicButton каждый используют animateFloatAsState и graphicsLayer (ConnectedCatalog.kt:203-216, BobylTvApp.kt:147-169, BobylTvApp.kt:188-205).
План:
- оставить масштабирование только для реально сфокусированного элемента;
- измерить влияние анимации на прокрутку;
- при наличии jank заменить масштаб на изменение border/background, либо перенести декоративное изменение в draw phase;
- не масштабировать контейнер, влияющий на геометрию lazy-списка;
- проверить быстрые последовательные нажатия D-pad и выход focus за края экрана.
6. Упростить отрисовку и overdraw
В Details одновременно используются backdrop, горизонтальный gradient и затемнение (ConnectedCatalog.kt:283-285). Нужно:
- оставить один основной scrim;
- убрать лишние полупрозрачные слои;
- ограничить тени и blur;
- проверить overdraw на реальном TV-устройстве;
- не добавлять видео-фон или постоянный shimmer без подтверждённой пользы.
7. Улучшить навигационное состояние
BobylTvApp сохраняет состояние экранов через rememberSaveableStateHolder и возвращает на Home через BackHandler (BobylTvApp.kt:88-102).
Проверить и закрепить:
- восстановление scroll position для каждого раздела;
- восстановление последней открытой карточки;
- возврат focus после закрытия Details, Comments и Playback;
- отсутствие повторной сетевой загрузки при простом возврате назад;
- корректное поведение при быстрой смене разделов.
8. Добавить профили производительности
После стабилизации UI создать Baseline Profile для маршрута:
Cold start → Home → scroll → Details → seasons/episodes → Back → Search → results scroll.
Добавить Macrobenchmark-сценарии:
- cold startup;
- Home scroll;
- Search scroll;
- Details open;
- Details scroll;
- Back restoration.
Профилировать только release-like сборку; debug-результаты не использовать как критерий производительности.
9. Accessibility и TV-проверки
До финального принятия проверить:
- все интерактивные элементы имеют минимум 48 dp;
- focus order соответствует визуальному порядку;
- D-pad не попадает в невидимые или уже выгруженные элементы;
- loading/error/empty состояния имеют понятный focus;
- TalkBack проходит маршрут Home → Details → Watch;
- увеличенный шрифт и длинные названия не ломают карточки;
- контраст текста и focus-индикатора достаточен.

Готовность: нет систематического jank в основных TV-сценариях, нет скачка размеров карточек при загрузке изображения, память стабилизируется после ухода с каталога, Back возвращает прежний экран и focus, а результаты подтверждены release-профилированием. ахәыҷ
